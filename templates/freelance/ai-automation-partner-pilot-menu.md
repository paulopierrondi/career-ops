# AI Automation Partner - Pilot Menu

Updated: 2026-06-22

Use this when the buyer wants an ongoing AI automation partner, technical partner, RevOps operator, n8n/Make/GHL builder, RAG engineer or internal AI workflow owner, but the scope is too broad to price safely.

Goal: convert broad demand into a small paid first milestone that proves value, preserves trust and avoids open-ended delivery risk.

## Client-Facing Principle

Start with a capped pilot, not a vague full build.

```text
The fastest safe path is a capped first pilot: one workflow, one measurable result, logs/tests, and a runbook. If that slice works cleanly, the larger engagement becomes easier to price and safer to execute.
```

## Pilot 1 - Automation Diagnostic + Hardening Sprint

Best for:

- unclear scope;
- broken automations;
- too many tools;
- agency/client work where reliability matters;
- buyer needs a technical partner but has not defined the first workflow.

Deliverables:

1. workflow and systems map;
2. failure-point and risk list;
3. data/access boundary;
4. one quick fix or prototype where safe;
5. phase-2 backlog with estimates.

Suggested price:

- Upwork: `$450-$750`, 2-4 days;
- 99Freelas: `R$450-R$750`, 2-4 days;
- Contra/Malt/direct: `$750-$1,500`, 3-5 days when the buyer is serious.

Proposal snippet:

```text
I would start with a capped automation diagnostic and hardening sprint. The output is not a generic document: you get the workflow map, failure points, access/data boundaries, one safe quick fix where possible, and a prioritized build plan for phase 2.
```

## Pilot 2 - Workflow Build Sprint

Best for:

- n8n/Make/Zapier;
- APIs/webhooks;
- CRM fields/stages;
- WhatsApp/email/SMS with approval gates;
- lead qualification;
- operational dashboards.

Deliverables:

1. one prioritized workflow slice;
2. structured input/output contract;
3. logs and error branch;
4. fallback or human approval gate;
5. test cases;
6. short runbook.

Suggested price:

- Upwork: `$650-$1,200`, 3-5 days;
- 99Freelas: `R$650-R$1.100`, 3-5 days;
- Contra/Malt/direct: `$1,200-$2,500`, 5-7 days.

Proposal snippet:

```text
For the first build sprint, I would choose one high-impact workflow and make it reliable: data mapping, workflow implementation, logs, fallback behavior, test cases and a runbook. The goal is one working slice your team can inspect and operate, not a black box.
```

## Pilot 3 - RAG / API / Agent Proof Sprint

Best for:

- knowledge-base assistant;
- chat over documents/data;
- ERP/API to structured AI output;
- internal copilot;
- agent workflow proof.

Deliverables:

1. source/data review;
2. answer/output schema;
3. small working proof with fake, redacted or approved test data;
4. 10-20 evaluation questions;
5. hallucination/fallback rules;
6. production-readiness notes.

Suggested price:

- Upwork: `$750-$1,500`, 4-7 days;
- 99Freelas: `R$900-R$1.800`, 4-7 days;
- Contra/Malt/direct: `$1,500-$3,500`, 1-2 weeks.

Proposal snippet:

```text
For a RAG/API/agent project, I would not jump directly into production. I would first build a small proof with structured output, evaluation questions, fallback rules and production-readiness notes. That lets us validate retrieval quality and risk before scaling.
```

## Screening Answers

### Why not quote the whole project now?

```text
Because a broad quote before seeing the data, workflow and access boundaries is usually either inflated or risky. A capped pilot gives you visible output first, then we price the larger build with real information.
```

### Can you work as an ongoing partner?

```text
Yes, but I would still start with a capped pilot. After the first slice proves the workflow and working style, ongoing work can move to weekly hours, monthly support or a backlog-based retainer.
```

### Can you start fast?

```text
Yes. The first step is to confirm the systems involved, test data or sandbox access, the one workflow that matters most, and which actions must stay human-approved.
```

## Guardrails

- No production credentials before contract and secure access path.
- No real sensitive data in chat, repo, email or screenshots.
- No off-platform contact where marketplace rules prohibit it.
- No guaranteed WhatsApp/Meta approvals.
- No CAPTCHA bypass, fake engagement, spam, scraping private accounts or unauthorized outreach.
- Keep client-facing language focused on outcomes, not Paulo's internal LLM/tool stack.
